# P41-BASIS R1 — frozen component API

`project_schedule_basis(*, scope, policy_version, source_action_id, state, policy, action, attempt, receipt, now) -> dict`

`ScheduleBasisError(ValueError)` имеет `.code`; `str(error)==code`, без входных данных. Допустимые коды: INVALID_INPUT, DEPENDENCY_REJECTED, SCOPE_MISMATCH, SOURCE_UNCONFIRMED, FENCED. Ни один не означает выполненную запись или отправку. Входы built-in JSON dict/list/str/int/bool/null; `now` — timezone-aware datetime. Отказ на malformed типах не должен утечь необработанным исключением. При нескольких дефектах приоритет не фиксируется, кроме запрета любых эффектов и выдачи basis до полной проверки.

## Исходные форматы и проверки

1. scope — exact dict пяти B8-06 полей: client_id,campaign_id,lead_id,mailbox_ref,thread_id. ID: plain str 1..128, без пробелов по краям, C0/DEL или не кодируемых в UTF-8 суррогатов. campaign_id — canonical lowercase UUID. Все пять обязательны, thread_id не null. policy_version/source_action_id — такой же ID. now имеет UTC offset, future last_outbound_at запрещён.
2. state и policy — полные original FIRST_DIALOGUE_STATE_V1/FIRST_POLICY_V1. Применить существующую публичную F103 `decide_next_action` как структурную проверку на внутреннем НЕСОХРАНЯЕМОМ AUTOREPLY событии: schema FIRST_DIALOGUE_EVENT_V1, event_id=`p41-validation`, scope из state, observed_at=now.isoformat(), kind=AUTOREPLY. Это только публичный validation path, не входящее письмо/decision/history. Его action не записывать и не превращать в предложение. Ошибка F103 → DEPENDENCY_REJECTED. До вызова валидации обеспечить builtin JSON domain; не вызывать пользовательские object hooks. Дополнительные допустимые original поля не удалять. Read-only source входит в reference.
3. state.runtime_campaign_id соответствует scope.campaign_id, остальные четыре равны; action.scope — exact тот же original scope с runtime_campaign_id. Политика sender_ref равна mailbox_ref. Любое несовпадение идентичности → SCOPE_MISMATCH. state.status STOPPED/HANDED_OFF → FENCED, ACTIVE необходим. state.policy не изобретать.
4. action — original FIRST_ACTION_INTENT_V1. Вызвать неизменный F114 `build_outbound_intent(action)` для полной проверки исходного action/payload/hash; ошибка → DEPENDENCY_REJECTED. Подготовленный объект не сохранять. HANDOFF source запрещён (SOURCE_UNCONFIRMED); SEND/REPLY/FOLLOWUP допустимы. action.action_id==source_action_id; action.policy_version==policy_version==policy.policy_version; action.locale==policy.locale; action.language_pack_version==policy.language_pack_versions[policy.locale]. Несовпадение → SCOPE_MISMATCH. expected_state_revision исходного action не обязан равняться текущему state.revision: source action предшествует последующим событиям; не вводить новую CAS-политику.
5. attempt и receipt — original FIRST_SEND_ATTEMPT_V1 / FIRST_PROVIDER_SEND_RESULT_V1 (receipt также может быть null по F108). Вызвать неизменный F108 `normalize_send_receipt(attempt,receipt)`. Ошибка → DEPENDENCY_REJECTED. Не реализовывать новый mapping outcome→state. Проверить scope/action_id/payload_sha256 результата по action; thread связывается через action.scope. Несовпадение → SCOPE_MISMATCH. Только original normalized ACCEPTED или DELIVERED дают basis; UNKNOWN/NOT_SENT → SOURCE_UNCONFIRMED. ACCEPTED не объявлять DELIVERED и не менять reconciliation_required.
6. last_outbound_at брать ТОЛЬКО из state. Строка должна быть RFC3339 `YYYY-MM-DDTHH:MM:SS[.1..6digits](Z|+HH:MM|-HH:MM)`, действительная дата, заданное смещение, `-00:00` запрещено. Не брать из now/observed_at/mtime/receipt text. null/malformed/future → SOURCE_UNCONFIRMED. UTC формат Python datetime.isoformat() с `+00:00` заменённым на Z; точность не терять. Provenance соответствия state timestamp к подтверждённому source action обязан гарантировать вызывающий trusted owner; у F108 timestamp отсутствует, компонент не может доказать это своим hash.
7. max_followups,cooldown_seconds из policy и followups_sent из state: exact int>=0 (bool запрещён), без своих defaults/округления. Ноль и уже достигнутый cap допустимы в basis: B8-06 сам откажет неподходящему schedule. Cooldown arithmetic overflow при подготовке совместимого basis должен быть SOURCE_UNCONFIRMED: last_outbound_at + timedelta(seconds=cooldown_seconds) должен представляться datetime.

## Результат и сохранность

Exact dict без schema_version/metadata/secret полей:
`{policy_version,source_action_id,source_state,last_outbound_at,max_followups,cooldown_seconds,followups_sent}`.
Значения из проверенных источников по правилам выше. Новый независимый dict; входы не мутируются, одинаковые входы дают равный результат. Исключения не содержат адресов/текста/секретов. Никакого I/O, глобального mutable state, времени системы, trusted=true или автоматического назначения прав.

## Совместимость и граница

Ответ полностью совпадает с B8-06 R3.1 `BASIS_FIELDS` и вызовом `Service._schedule`; он не меняет schedule identity `[scope,policy_version,source_action_id,ordinal]`, replay-before-current-basis, cooldown/cap, cancel/tick или F103 policy. Existing P15 decision codec и original accepted B806 остаются read-only. Новая функция — адаптер проекции, не новый owner состояния.
